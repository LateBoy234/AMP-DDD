# 第 1 步：从一个位置理解 Domain

本次只新增 `src/AMP.Domain/Motion/Position3D.cs`，保留目录中原有的计量代码。先只看这一个类型，不需要一次理解整个项目。

## 1. Domain 解决什么问题

Domain 是领域层，用代码表达软件所处理的业务概念和规则。在自动测量软件中，位置、测量点、标准色砖、测量结果都可能是领域概念。

判断一段代码是否适合放在这里，可以先问：即使把 WPF 界面换掉，把运动控制卡换掉，这个概念和规则是否依然存在？

“目标位置有 X、Y、Z 三个坐标”依然成立；“调用某厂商 DLL 发送运动指令”则与设备实现有关。因此本类只表达位置，不调用 DLL，不打开串口，不操作界面。

## 2. 为什么先写 Position3D

自动测量需要先知道到哪里测量。用一个小对象讲清楚职责和数据约束，比先搭很多接口更容易理解。

```csharp
using AMP.Domain.Motion;

var first = new Position3D(x: 10, y: 20, z: 5);
var same = new Position3D(x: 10, y: 20, z: 5);

Console.WriteLine(first == same); // True：坐标相同，位置相同。

// first.X = 100;                  // 编译不通过：创建后不能修改。
// var changed = first with { X = double.NaN }; // 同样不能绕过构造校验。
// new Position3D(double.NaN, 0, 0); // 抛出异常：非法数值不能成为一个位置。
```

该片段是阅读示例，不是另一个需要实现的程序。

## 3. 每个设计选择的原因

| 选择 | 要解决的问题 | 当前边界 |
| --- | --- | --- |
| 三个坐标组合成一个对象 | 让“位置”成为明确概念，避免散落的参数 | 构造时仍需注意坐标顺序，示例使用命名参数 |
| 使用 double | 表达毫米坐标和小数位置 | 以后若有真实精度需求，再明确舍入或容差规则 |
| 单位统一为毫米 | 防止同一层混用毫米和脉冲 | 控制卡适配器负责毫米到脉冲的换算 |
| 使用 record | 坐标相同的位置按值相等 | 精确相等不代表机械运动已到位，到位容差另定 |
| 使用 sealed class 形式的 record | 不需要继承，也避免结构体默认构造绕过校验 | null 仍要由使用者在入口处理 |
| 只读属性 | 防止位置被共享代码悄悄修改 | 新位置用构造函数创建 |
| 构造时拒绝 NaN 和无穷 | 一开始就拦截无意义的坐标 | 不随意添加未知的设备行程限制 |

注意：`new Position3D(10, 20, 5)` 只创建数据，不会让设备移动。负坐标合法也不代表设备允许移动到该位置。

## 4. 这一步学到的框架思维

先确认一个对象负责什么，再决定它提供什么行为。位置负责表达三个合法的毫米坐标；控制运动、选择测量计划、保存记录分别是其他职责。

当前还没有重复需求，不引入 `IPosition`、通用值对象基类、依赖注入容器或运动服务。框架应随着具体职责逐步形成。

下一步可以写“测量点”：它把点位名称和位置关联起来。先想清楚测量点与位置的区别，再动手；本轮不提前实现。
